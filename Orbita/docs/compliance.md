# Выгрузка данных по законному запросу (комплаенс)

Легальная «передача данных» — это когда оператор по письменному запросу уполномоченного органа выгружает то,
что **реально есть** в базе, в структурированном виде, и каждый такой доступ протоколируется. Никакого скрытого
или автоматического канала выдачи в коде нет и не будет — перехват по закону оформляется открыто (СОРМ,
см. `docs/legal-russia` ниже), а не маскируется внутри приложения.

## Что включено

Ручки администратора (отдельный токен, **не** пользовательский):

- `GET /v1/admin/export/<user_id>` — структурированная выгрузка по пользователю: профиль (имя, @username,
  телефон, bio — расшифрованные), личная переписка (расшифрованный текст + метаданные: кто, кому, когда,
  прочитано), **метаданные** звонков, членство в группах, список медиа (метаданные). Фильтр по времени:
  `?from=<unix>&to=<unix>`.
- `GET /v1/admin/media/<id>` — расшифрованный файл (для приложения к выгрузке).
- `GET /v1/admin/access-log` — журнал обращений администратора (кто/когда/к чьим данным).

## Безопасность этих ручек

- **По умолчанию выключены.** Пока не задан `ORBITA_ADMIN_TOKEN`, все три ручки отвечают `404` — их как будто нет.
- Доступ только по заголовку `X-Admin-Token`, сравнение постоянное по времени. Токен — отдельный от
  пользовательских, храните его в секрете и выдавайте только сотруднику, отвечающему за ответы на запросы.
- **Каждое** обращение пишется в `admin_access_log` (метка `X-Admin-Label`, действие, чьи данные, IP, время) —
  подотчётность: видно, кто и к каким данным обращался.
- Ставьте эти пути за дополнительным ограничением на уровне nginx (allowlist по IP офиса/VPN).

```bash
export ORBITA_ADMIN_TOKEN="длинная-случайная-строка"
# пример запроса:
curl -H "X-Admin-Token: $ORBITA_ADMIN_TOKEN" -H "X-Admin-Label: compliance-ivanov" \
     "https://ваш-домен/v1/admin/export/<uuid>?from=1700000000"
```

## Про звонки: нужно ли выдавать содержание разговоров?

Коротко: **содержание звонков выдать нельзя — его нет на сервере.** Звонки сквозные (DTLS-SRTP), ключи только
на телефонах собеседников; сервер лишь передаёт сигналы и разговор не слышит. Поэтому:

- **Метаданные звонков** (кто, кому, когда, длительность, тип) — есть, лежат в `call_log`, выгружаются.
- **Содержание** — физически отсутствует. Чтобы его получить, нужно либо отказаться от сквозного шифрования
  звонков (тогда сервер сможет записывать — но это надо честно показать пользователям, звонки перестанут быть
  приватными), либо организовать законный перехват на стороне оператора (СОРМ). Это **политическое/юридическое
  решение владельца**, а не то, что включается незаметно в коде. По умолчанию звонки остаются сквозными, и
  сервер отдаёт по ним только метаданные.

Переписка и файлы — другое дело: они шифруются ключом **сервера** (шифрование на диске, не сквозное), сервер их
расшифровывает штатно, поэтому их содержание выгрузить можно (что и делает `admin/export`).

## Срок хранения (ретенция)

`ORBITA_RETENTION_DAYS` — справочная настройка срока хранения. Важная оговорка: сейчас, когда пользователь
удаляет сообщение, оно **удаляется по-настоящему**. Требование «хранить даже после удаления пользователем в
течение срока Х» (пакет Яровой) — это отдельная политика: её включение меняет поведение удаления и должно быть
сознательным решением оператора (и честно отражено в политике конфиденциальности). По умолчанию удаление
остаётся удалением — приватность пользователя не ослабляется молча.

## Юридическая рамка (РФ)

Это техническая возможность ответить на законный запрос. Сам по себе комплаенс в РФ (реестр ОРИ, хранение
данных на территории РФ по 242-ФЗ/152-ФЗ, сроки по пакету Яровой, оборудование СОРМ по приказу Минцифры № 571,
передача ключей по приказу ФСБ № 432) требует регистрации, сертифицированного оборудования и **юриста по
IT/связи + лицензированного интегратора СОРМ**. Код даёт только структурированную выгрузку и журнал доступа —
остальное оформляется организационно и не является частью приложения.

Это не юридическая консультация.
