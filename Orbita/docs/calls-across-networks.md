# Звонки между разными сетями

Звонок в WebRTC идёт **напрямую между телефонами**, а сервер только передаёт сигналы и ключи (разговор
зашифрован сквозным DTLS-SRTP, сервер его не слышит). Чтобы два телефона в разных сетях нашли друг друга,
нужны вспомогательные серверы:

- **STUN** — помогает телефону узнать свой внешний IP и порт. Уже настроен (публичные серверы Google), денег не стоит.
- **TURN** — ретранслятор. Когда прямое соединение невозможно (мобильный интернет, CGNAT, строгий фаервол — а это
  большинство случаев «разных сетей»), звук и видео идут через него. **Без TURN звонки между разными сетями часто
  не соединяются — это устройство WebRTC, а не ошибка приложения.** В одном Wi-Fi TURN не нужен, потому что телефоны
  видят друг друга напрямую, поэтому «в одном вай-фае работает, а между сетями нет».

## Что уже сделано в коде

- Клиент заранее собирает ICE-кандидаты и перебирает пути быстрее; пока звонок соединяется, кандидаты
  забираются с сервера каждые 250 мс (раньше — 700 мс, из-за чего связь успевала сорваться).
- Сервер отдаёт STUN всегда, а TURN — если он настроен (см. ниже).

## Поднять свой TURN (coturn)

На любом сервере с белым IP (VPS за 3–5 $/мес хватает):

```bash
sudo apt install coturn
```

`/etc/turnserver.conf`:

```
listening-port=3478
tls-listening-port=5349          # и/или 443 — проходит через фаерволы, которые режут всё кроме веба
fingerprint
use-auth-secret
static-auth-secret=ДЛИННАЯ_СЛУЧАЙНАЯ_СТРОКА
realm=turn.ваш-домен
total-quota=100
cert=/etc/letsencrypt/live/turn.ваш-домен/fullchain.pem
pkey=/etc/letsencrypt/live/turn.ваш-домен/privkey.pem
no-tcp-relay
```

Открой порты `3478`, `5349` (и `443`, если используешь), а также диапазон `49152–65535/udp`.

## Включить TURN в Orbita

Серверу Orbita передаются переменные окружения:

```bash
export ORBITA_TURN_URL="turn:turn.ваш-домен:3478?transport=udp,turns:turn.ваш-домен:443?transport=tcp"
export ORBITA_TURN_SECRET="ДЛИННАЯ_СЛУЧАЙНАЯ_СТРОКА"   # тот же static-auth-secret
export ORBITA_TURN_TTL=86400                          # на сколько секунд годен выданный логин (по умолчанию сутки)
```

С `ORBITA_TURN_SECRET` сервер выдаёт на каждый звонок **временный логин-пароль** (механизм coturn `use-auth-secret`):
пароль нельзя переиспользовать, постоянный пароль нигде не лежит. Если проще — можно задать постоянные
`ORBITA_TURN_USER` / `ORBITA_TURN_PASS` вместо секрета.

`turns:…:443?transport=tcp` в списке важен: это TURN поверх TLS на 443 порту. Такой адрес проходит почти через
любой корпоративный или публичный Wi-Fi, который блокирует обычные порты.

## Проверить

1. Запусти coturn, пропиши переменные, перезапусти сервер Orbita.
2. Открой https://icetest.info или webrtc.github.io/samples/src/content/peerconnection/trickle-ice/ — впиши адрес
   TURN и логин (их можно подсмотреть в ответе `POST /v1/calls`), убедись, что приходят кандидаты типа **relay**.
3. Позвони с телефона по мобильному интернету на телефон в Wi-Fi.

Если relay-кандидаты есть, а звонок всё равно не соединяется — проверь, что на сервере coturn открыт диапазон
UDP-портов, и что `external-ip` указан, если coturn стоит за NAT (например, в облаке с внутренним IP).

## Про «передачу данных властям»

Я сознательно не встраиваю в звонки механизм скрытой выдачи разговоров третьей стороне. Сквозное шифрование
(DTLS-SRTP) означает, что сервер не имеет ключей и не слышит разговор. Любой «второй получатель ключей» внутри
такой схемы — это бэкдор, который ломает приватность для всех пользователей и делает сам механизм главной мишенью.
Поэтому звонки остаются честно сквозными. Если по закону оператору связи положен перехват, его оформляют открыто
и отдельно, а не маскируют под сквозное шифрование — тогда и пользователю честно показывают, что звонки не E2E.
