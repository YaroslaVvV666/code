# Меню зажатого сообщения: что сделано для скорости

Swift в облачной среде не собирается: всё ниже нужно собрать в Xcode и проверить на iPhone
(длинный чат 500+ сообщений, фото / видео / голосовые / файлы / пересланный шортс).

## Изменения

| Где | Что было | Что стало |
|---|---|---|
| `ChatModel.refresh()` | раз в секунду заново присваивал `peer`, `typing`, `lastSeen`, `group`, `loaded`… — каждое присваивание `@Published` перерисовывало весь `ChatScreen` (и открытое меню), даже без изменений | присваивается только то, что изменилось |
| `MessageActionOverlay` | `@ObservedObject var model` — меню вместе с копией сообщения перерисовывалось на каждую публикацию модели, в том числе во время анимации появления | `let model` без подписки: всё нужное читается один раз |
| Ряд реакций | `LottieEmojiView(playing: settled).id(settled)` — через 0.25 с все 13 вью пересоздавались, в одном кадре строились все Lottie-сцены, JSON разбирался в момент открытия | `ReactionBarEmoji`: сразу стоит снимок **первого** кадра, через 0.2 с эмодзи оживают волной (шаг 35 мс), вью не пересоздаётся |
| `LottieEmojiView` | слот в `PlaybackGate` брался только в `onAppear`; смена `playing` false → true не перезапускала круг | слот берётся при старте, `playing` false → true сбрасывает `finished` и играет заново; новый параметр `idleAtStart` |
| `PlaybackGate` | лимит 12 | 16 (ряд ~10 видимых + чат) |
| Прогрев | `preloadAll` пропускал разбор JSON, если есть снимок на диске → разбор шёл при открытии меню | `LottieEmojiStore.warm` через 0.8 с после входа в чат разбирает анимации вне главного потока; `preloadAll` готовит снимки и первого, и последнего кадра |
| Подложки меню (iOS < 26) | `.glass` = `.ultraThinMaterial` + тень по содержимому поверх уже размытого экрана | почти непрозрачная заливка, тень по форме; на iOS 26 — по-прежнему системное стекло |
| Отклик на касание | ничего до срабатывания зажатия (0.25 с) | пузырь плавно сжимается до 0.96 сразу при касании (с задержкой 50 мс), хаптик готовится заранее (`Haptics.prepare`); порог 0.25 с / 8 pt не менялся |
| `Haptics` | новый генератор на каждый отклик | генераторы переиспользуются |
| `ReactionEffectLayer` | 21 `Text` с пересчётом шрифта на каждом кадре, `TimelineView(.animation)` до 120 fps, точка вылета (поиск по `model.messages`) считалась для каждой частицы | один `Canvas` с заранее отрисованными символами, 60 fps, точка вылета — раз за кадр, слой живёт 1.8 с вместо 2 |
| `DustDissolve` | каждая песчинка — отдельный `fill` (тысячи вызовов на кадр в маске и в облаке) | маска — один путь и одна заливка; облако — 16 путей (2 цвета × 8 ступеней прозрачности) |

Не менялось сознательно: `ActionTargetState` / `ActionTargetHost`, размытие на весь экран без анимации прозрачности,
жесты в `MessageRow` (пороги), `server.py`. Новых Swift-файлов нет — в Xcode-проект ничего добавлять не нужно.

## Что проверить на телефоне

1. Зажатие текста, фото, голосового, файла, шортса: пузырь сжимается сразу, меню появляется плавно,
   реакции стоят статично и оживают волной без «скачка» картинки.
2. Медленное начало прокрутки и быстрый флик: прокрутка не перехватывается, пузырь под пальцем почти не дёргается.
3. После зажатия фото просмотр не открывается; свайп-ответ работает.
4. Реакция из ряда, двойной тап, повторное нажатие снимает реакцию; крупный эффект выглядит как раньше.
5. Удаление: подтверждение, пыль (сравнить с прошлым видом — плотность та же, прозрачность ступенчатая), сдвиг списка.
6. iOS < 26: вид подложек меню стал плотнее (без второго размытия) — оценить, устраивает ли.

## Как мерить (Instruments)

- **SwiftUI** template → *View Body*: открыть меню 5 раз. `ChatScreen` и `MessageRow` не должны появляться
  в момент открытия; раньше `ChatScreen.body` срабатывал ещё и каждую секунду от опроса.
- **Animation Hitches**: открыть/закрыть меню на длинном чате, удалить большое фото — hitch-time ≈ 0.
- **Time Profiler**: интервал «касание → первый кадр меню»; искать `LottieAnimation.from`, `MainThreadAnimationLayer`,
  `CoreAnimationLayer` — их не должно быть в первом кадре.

## Что ещё можно сделать, если будет мало

- Копия сообщения в меню — живой `MessageRow`. Для тяжёлых пузырей (превью ссылок, альбомы) можно рисовать
  упрощённую копию. Снимок через `ImageRenderer` не подходит: он не рисует видео, UIKit-вью и материалы.
- `MessageFrameKey`: каждая видимая строка и каждый чип реакции отдают `.global`-рамку на каждом кадре прокрутки.
  Нужна она только для точки вылета эффекта — можно искать рамку лениво (через `onGeometryChange` на iOS 18+).
- `DustDissolve` переключает структуру вью (`if active`), из-за этого строка пересоздаётся в момент начала удаления.
