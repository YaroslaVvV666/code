# Меню зажатого сообщения: что сделано для скорости

Swift в облачной среде не собирается: всё ниже нужно собрать в Xcode и проверить на iPhone
(длинный чат 500+ сообщений, фото / видео / голосовые / файлы / пересланный шортс).

## Изменения

| Где | Что было | Что стало |
|---|---|---|
| `ChatModel.refresh()` | раз в секунду заново присваивал `peer`, `typing`, `lastSeen`, `group`, `loaded`… — каждое присваивание `@Published` перерисовывало весь `ChatScreen` (и открытое меню), даже без изменений | присваивается только то, что изменилось |
| `MessageActionOverlay` | `@ObservedObject var model` — меню вместе с копией сообщения перерисовывалось на каждую публикацию модели, в том числе во время анимации появления | `let model` без подписки: всё нужное читается один раз |
| Ряд реакций | `LottieEmojiView(playing: settled).id(settled)` — через 0.25 с все 13 вью пересоздавались, в одном кадре строились все Lottie-сцены, JSON разбирался в момент открытия | `ReactionBarEmoji`: анимация стартует сразу при открытии меню (первый кадр меню — только готовые картинки, дальше эмодзи запускаются по одному на кадр, ~16 мс), вью не пересоздаётся |
| `LottieEmojiView` | слот в `PlaybackGate` брался только в `onAppear`; смена `playing` false → true не перезапускала круг | слот берётся при старте, `playing` false → true сбрасывает `finished` и играет заново; новый параметр `idleAtStart` |
| `PlaybackGate` | лимит 12 | 16 (ряд ~10 видимых + чат) |
| Прогрев | `preloadAll` пропускал разбор JSON, если есть снимок на диске → разбор шёл при открытии меню | `LottieEmojiStore.warm` через 0.3 с после входа в чат разбирает анимации вне главного потока; `preloadAll` готовит снимки и первого, и последнего кадра |
| Подложки меню (iOS < 26) | `.glass` = `.ultraThinMaterial` + тень по содержимому поверх уже размытого экрана | почти непрозрачная заливка, тень по форме; на iOS 26 — по-прежнему системное стекло |
| Отклик на касание | — | **убран**: сжатие пузыря через `@GestureState` + `LongPressGesture.updating` на свежих iOS перехватывало касание и ломало прокрутку чата. Не возвращать: жест зажатия в `MessageRow` — без `.updating` |
| `Haptics` | новый генератор на каждый отклик | генераторы переиспользуются |
| `ReactionEffectLayer` | 21 `Text` с пересчётом шрифта на каждом кадре, `TimelineView(.animation)` до 120 fps, точка вылета (поиск по `model.messages`) считалась для каждой частицы | один `Canvas` с заранее отрисованными символами, 60 fps, точка вылета — раз за кадр, слой живёт 1.8 с вместо 2 |
| Удаление (`MessageDust`) | пыль двух цветов темы поверх строки, строка ждала 0.95 с и только потом уходила из списка | как в Telegram: сообщение рассыпается частицами своих же цветов. Снимок экрана на месте сообщения → строка прячется → второй снимок; где пиксели изменились — там пузырь (обои не рассыпаются). Частицы (до ~4000, клетки от 2 pt) рисуются раз в кадр в отдельном прозрачном окне поверх чата, поэтому строка уходит из списка, пока пыль ещё летит. Частицы отрываются мягко (разгон без рывка), покачиваются и плавно тают; кадры до 120 Гц. Соседние сообщения съезжают пружиной через ~0,1 с после начала. Видео перед снимком на миг показывает превью-кадр (`mediaFrozen`): живой видеослой iOS в снимок не отдаёт |
| Кэш кадров (`EmojiFrames`) | каждое воспроизведение мелкого эмодзи строило Lottie-сцену и пересчитывало её 30 раз в секунду на главном потоке | при первом запуске каждое эмодзи один раз рисуется в кадры (30 кадров/с, под 34 pt × масштаб экрана) и навсегда сохраняется в Application Support (без бэкапа); при каждом запуске кадры подхватываются с диска (mmap), все анимации разбираются сразу. Эмодзи до 48 pt (ряд реакций, реакции под сообщением, панель) играют готовыми кадрами через `CADisplayLink`, кадр разжимается в фоне. Поменяли JSON — кадры перерисуются сами (в имени файла отпечаток анимации) |
| Положение и клавиатура | меню по центру экрана; с открытой клавиатурой оказывалось под ней | копия сообщения стоит там же, где сообщение в переписке (`sourceFrame` из `MessageFrameKey`), сверху реакции, снизу кнопки; сдвигается, только если не влезает. Меню — в отдельном окне выше клавиатуры (`MessageMenuWindow`, не key window — фокус поля ввода не теряется); в окно явно передаются theme, lang, AppSession, AuthFlow, AudioPlayer |
| Прокрутка переписки | подгрузка ранних сообщений перекидывала экран (`scrollTo(firstKey, .top)`), весь список анимировался на любую смену id | `scrollPosition(id:)` + `scrollTargetLayout()` держат видимое сообщение на месте при добавлении сверху и росте контента; ранние подгружаются за ~1200 pt до верха; анимация только для нового внизу (`value: list.last?.id`); позиция — в `ScrollAnchorBox` (класс), чтобы прокрутка не перерисовывала `ChatScreen` |
| Касания под меню | палец, которым зажали сообщение, продолжал свайпать ответ и листать чат под размытием; во время закрытия касания проходили насквозь | пока меню открыто (`MessageMenu.isOpen`), строка не реагирует на свайп-ответ, двойной тап, фото/видео/файл/голосовое, цитату, звонок, реакции; список не листается (`ActionScrollLock` → `scrollDisabled`, без перерисовки строк); размытый фон ловит все касания и во время закрытия |
| Появление и закрытие меню | проявление из прозрачности могло «застревать», закрытие — в один кадр | сообщение видно сразу и мягко «приподнимается» (0.96 → 1), ряд реакций вырастает из угла над ним, список действий — из угла под ним (пружина 0.34 с, очередь 0–50 мс); эмодзи «выпрыгивают» волной по 25 мс и сразу играют. Закрытие (тап мимо, реакция, любое действие) — плавное, 0.17 с, потом действие. Размытие на весь экран по-прежнему без анимации |

Не менялось сознательно: `ActionTargetState` / `ActionTargetHost`, размытие на весь экран без анимации прозрачности,
жесты в `MessageRow` (пороги), `server.py`. Новых Swift-файлов нет — в Xcode-проект ничего добавлять не нужно.
Первый запуск после установки: кадры рисуются в фоне ~10–15 с маленькими порциями; пока их нет, эмодзи играют через Lottie, как раньше.

## Что проверить на телефоне

1. Зажатие текста, фото, голосового, файла, шортса: пузырь сжимается сразу, меню появляется плавно,
   реакции начинают играть сразу, без «скачка» картинки.
2. Медленное начало прокрутки и быстрый флик: прокрутка не перехватывается, пузырь под пальцем почти не дёргается.
3. После зажатия фото просмотр не открывается; свайп-ответ работает.
4. Реакция из ряда, двойной тап, повторное нажатие снимает реакцию; крупный эффект выглядит как раньше.
5. Удаление: подтверждение, сообщение рассыпается частицами своих цветов (сердце — красными и белыми), соседние сразу съезжают.
6. iOS < 26: вид подложек меню стал плотнее (без второго размытия) — оценить, устраивает ли.

## Как мерить (Instruments)

- **SwiftUI** template → *View Body*: открыть меню 5 раз. `ChatScreen` и `MessageRow` не должны появляться
  в момент открытия; раньше `ChatScreen.body` срабатывал ещё и каждую секунду от опроса.
- **Animation Hitches**: открыть/закрыть меню на длинном чате, удалить большое фото — hitch-time ≈ 0.
- **Time Profiler**: интервал «касание → первый кадр меню»; искать `LottieAnimation.from`, `MainThreadAnimationLayer`,
  `CoreAnimationLayer` — их не должно быть в первом кадре.

## Что ещё можно сделать, если будет мало

- Копия сообщения в меню — живой `MessageRow`. Для тяжёлых пузырей (превью ссылок, альбомы) можно рисовать
  упрощённую копию. Снимок через `ImageRenderer` не подходит: он не рисует видео, UIKit-вью и материалы.
- `MessageFrameKey`: каждая видимая строка и каждый чип реакции отдают `.global`-рамку на каждом кадре прокрутки.
  Нужна она только для точки вылета эффекта — можно искать рамку лениво (через `onGeometryChange` на iOS 18+).
